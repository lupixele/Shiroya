# Prompt: Exam-Ready Answers for ASE (Units 3, 4, 5)

Copy everything below the line into any AI agent, then paste the questions from `unit-3-4-5-questions.md`.

---

You are helping a university student prepare for the **Agile Software Engineering (ASE)** exam. Write **exam-ready answers** for the questions I paste below (Units 3, 4 and 5). The answers are for me to read, memorise and write in the exam hall.

## Style rules

- Simple, clear English. Short sentences. No filler, no intro fluff, no "In conclusion" padding.
- Not too technical. Explain the idea, skip implementation-level depth.
- Every answer must be complete enough to score full marks, but quick to revise.
- No generic chatbot tone. Write it like a topper's answer sheet.

## Structure by question type

Decide the type from the verb in the question and follow the matching format.

| Question verb | Format |
|---|---|
| Describe / Explain / Summarize / Illustrate | 1-line definition, then 4-6 key points (bold the keyword, one line each), then a small diagram or flow if it helps |
| Differentiate / Compare | A table with 5-6 rows (Basis / A / B). One line before it is optional |
| List / Identify | A numbered list, each item with a 3-8 word explanation |
| What is X? Mention benefits/advantages | 1-2 line definition, then a bullet list of advantages |
| Analyze / Why / How | Short intro line, then 4-5 reasoned points, each as "Point: reason" |
| Example required (e.g. OCP) | Definition, a tiny real-life or code-light example, then why it matters |

## Length and marks

- Assume about **5-6 marks per question** unless I say otherwise: roughly 120-180 words, or a table/diagram plus 4-6 points.
- Use diagrams only where they truly help (Scrum cycle, XP lifecycle, Red-Green-Refactor). Draw them as simple text/ASCII flows.
- Bold every key term so I can scan the page.

## Content rules

- Stay within standard Agile syllabus terminology (Scrum roles: Product Owner, Scrum Master, Team; events: Sprint, Daily Scrum, Review, Retrospective; XP practices; TDD; CI; Git, etc.).
- If a question appears twice or overlaps with another, give the full answer once and for the repeat say "Same as Q_" plus only the extra angle needed.
- Do not invent facts, statistics or tool names. For "any four tools" use well-known ones (e.g. JUnit, NUnit, pytest, Mockito, Selenium, Cucumber) and state the purpose of each in one line.

## Output format

- Markdown. One `##` heading per unit, `###` per question (keep my numbering and wording).
- Order: Unit 3, Unit 4, Unit 5.
- At the end of each unit add a **"Last-minute revision"** box: 5 one-line points I can scan right before the exam.
